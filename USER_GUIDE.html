1. Quick start

Choose a coding model → Static Analysis → Dynamic Analysis → Optimization → Save or export

  1. Launch the installed app from the Start menu, run the portable executable from its application folder, or use start.bat from a source checkout.
  2. Above the tab menu, set The code will run with to the coding provider and model whose costs you want to estimate.
  3. Open Static Analysis, paste your repository's absolute folder path, and select Analyze.
  4. Open Dynamic Analysis, enter a supported session-log folder, and select Analyze. Add the repository path if you want to filter relevant sessions and compare usage.
  5. Open Optimization, choose standard or Deep Analysis, and select Generate Optimization Suggestions.
  6. Review proposed changes and savings. Use Save Analyses for a restorable snapshot or an export button for a shareable report.
Static analysis works on its own. You only need both static and dynamic results when using the Optimization Advisor.

2. Install and launch

Windows MSI or portable application

On Windows x64, run the MSI to install for your user account, then open AI Usage Analyzer from the Start menu. To use the portable build instead, keep its entire application folder together and open AI-Usage-Analyzer.exe inside it. The executable requires the other files in that folder. Both packages include Node.js and production dependencies; Windows 10/11, .NET Framework 4, and a web browser are required. The launcher opens the default browser using an available local port. An unsigned build may trigger a Windows security warning; only run packages you trust.

Packaged-app settings and credentials are stored in %LOCALAPPDATA%\AI Usage Analyzer\.env; saved analyses and session state are stored in the Session and session_state subfolders there. Uninstalling the MSI leaves this private data in place. Delete it manually only if you no longer need it. The packaged launcher does not open command windows.

Requirements

  • Windows, a current web browser, and read access to the repository and session-log folders.
  • Node.js 20.19 or newer in the 20.x series, or Node.js 22.12 or newer, with npm available.
  • For cloud optimization only: a Copilot-enabled account or an Anthropic API key, plus network access.

First-time setup from source

Open PowerShell in the project root and install dependencies for both application components:

Push-Location .\backend
npm.cmd ci
Pop-Location
Push-Location .\frontend
npm.cmd ci
Pop-Location
.\start.bat

The launcher starts two development-server windows and opens http://localhost:5173. The backend normally listens on port 4000. If the browser opens before startup finishes, wait for the servers to be ready and refresh. Select Exit in the app to stop both servers and close the windows created by the launcher; unrelated terminals are not closed. Servers started manually must be stopped in their own terminals. The launcher does not watch backend source files for changes; restart it after backend edits.

Manual startup

Alternatively, run these commands in two separate PowerShell windows opened at the project root:

# Window 1
Set-Location .\backend
npx.cmd tsx src/server.ts

# Window 2
Set-Location .\frontend
npm.cmd run dev

Use npm.cmd if PowerShell blocks npm.ps1. If a port is already in use, inspect the server output rather than stopping unrelated processes.

Leaving the app

Save your analyses, then select Exit to request backend shutdown. Your browser may refuse to close the tab automatically; close it manually if necessary. Development-server or watcher windows may remain open; use Ctrl+C in those windows when finished.

There are two separate selectors. They serve different purposes.

The coding-model dropdown currently contains:

  • GitHub Copilot: Claude Opus 4.8, Claude Sonnet 4.6, and GPT-5.3 Codex.
  • Claude Code: Claude Opus 4.8 and Claude Sonnet 4.6.
  • Ollama Cloud: run Static Analysis on the target repository first. Detected candidates appear in the dropdown; select one and rerun Static Analysis. Selection does not confirm the code actually invokes it.

Open Settings with the gear icon to the right of Exit in the header. The Settings popup contains the User Guide link, key replacement, and analysis preferences.

Check the provider group when selecting Claude models: the same model can appear under both providers. This list is the app's supported pricing catalog, not every model available from the providers.

Not a runtime setting: this selector does not run your repository, configure your IDE, or switch the model in an external coding assistant. It changes the assumptions used for estimates.

Changing the coding model clears current static and optimization results; rerun static analysis for the new model. Existing dynamic costs refresh automatically without rereading logs. Recorded token counts and logged model names are retained; costs are selected-model scenarios, not historical bills. Changing the Optimization LLM currently clears the analysis results as well, so choose it before starting or save a snapshot first.

Ollama detection looks for quoted cloud-tagged literals or cloud-tagged ollama run and ollama pull commands, literal model settings in files containing an ollama.com endpoint, and Ollama-named model settings in other files when such an endpoint exists. These are uncertain candidates and may be unrelated. Dynamic configuration, other unquoted values, unsupported files and excluded files may be missed. Files beginning .env are not scanned; no repository code is executed.

Cloud optimization authentication

GitHub Copilot: use Copilot CLI sign-in, stored GitHub CLI credentials for an account with Copilot access, or a backend COPILOT_GITHUB_TOKEN environment variable. An ordinary GitHub token without Copilot access is insufficient. Optionally set COPILOT_MODEL in the configured .env file to a model available to your account; otherwise Copilot chooses its default.

Copilot optimization retains SDK sessions using the base directory %USERPROFILE%\.copilot; workspaces are normally under %USERPROFILE%\.copilot\session-state\<session-id>. They can contain source excerpts, prompts, and responses, so protect them as private data. Storage does not guarantee token usage is recorded or compatible with Dynamic Analysis, and previously deleted sessions cannot be restored by enabling it.

Claude Code: configure ANTHROPIC_API_KEY in the backend environment or backend\.env. A Claude web subscription does not replace an API key for this integration.

Restart the backend after manually changing environment settings. Keys replaced through Settings take effect immediately. Never commit credentials. The coding-model cost selector does not change the cloud optimizer's backend model configuration.

4. Static Analysis

  1. Select the coding model above the tab menu.
  2. In Settings, decide whether to exclude generated files and lockfiles. Exclusion is enabled by default.
  3. Open Static Analysis and enter an absolute directory path such as D:\Projects\MyApplication. Paste the path without surrounding quotes.
  4. Select Analyze. The progress area shows the current file, scan counts, and an estimated remaining time when enough progress has been measured.

Results include file and line counts, estimated tokens, a language breakdown, the largest files, platform metrics, and general optimization suggestions. Excluded detected lockfiles are listed separately.

Cost basis: the static USD amount estimates one uncached input pass over the counted repository text. It is not a forecast of the full cost to develop the project, generate all its code, or conduct repeated sessions.

What is scanned?

Supported extensions include Python, JavaScript/JSX, TypeScript/TSX, Java, Go, C#, C++, Rust, JSON, YAML, TOML, Markdown, text, and Terraform; Dockerfile is also recognized. Unsupported file types are not counted.

The scanner skips node_modules, .git, dist, build, and vendor directories, files larger than 2 MiB, and files containing null bytes. The generated-file setting does not override these exclusions.

Clear removes the repository path and current static results, including the associated optimization result. It does not delete repository files.

5. Dynamic Analysis

Dynamic analysis reads supported local AI session logs. It does not retrieve provider billing records.

FieldWhat to enter
Session Files PathAn existing directory containing Claude Code .jsonl history or legacy Copilot CLI session folders with events.jsonl. For Claude, an example is C:\Users\YourName\.claude\projects. Replace YourName with your Windows account folder.
Code Repository Path (optional)An existing repository directory. The Static Analysis path is copied here as you enter it; you may edit or clear this field. This retains sessions with recognized code-creation/edit tools targeting that directory and attempts a static-size comparison. Omitting it includes all supported discovered sessions.

Select Analyze. Discovery searches subdirectories to a bounded depth. Use a closer parent folder if logs are nested too deeply. Enter expanded absolute paths; do not assume placeholders such as %USERPROFILE% are expanded in the input box.

Reading the results

  • Input/output/cache tokens: Claude usage fields come from supported logs. Copilot input tokens are estimated from content; its supported output-token values come from the logs.
  • Backend Models Used in Sessions: shows recorded model names for history. Cost estimates use the coding-model selector, not those historical model names. Recorded token counts are not retokenized.
  • Sessions: lists up to 10 highest-token sessions. Select View flow for available prompts, touched files, tool usage, and a session PDF export.
  • Daily usage: groups recorded activity by date.
  • Actual Usage vs. Codebase Estimate: compares input-plus-output usage with static repository size. A ratio above 1 is possible because sessions can load context repeatedly; it is not, by itself, proof of waste.
Filtering is session-level. A repository filter selects matching sessions and trims some file/tool details; it does not isolate a precise per-repository share of every token in a mixed-purpose session.

Current desktop Copilot binary storage under %LOCALAPPDATA%\github-copilot\pc\chat-agent-sessions is not supported. Microsoft 365 Copilot audit/Graph dynamic exports are not supported in this interface.

6. Optimization

First run or load both Static Analysis and Dynamic Analysis. The advisor combines repository information with the supplied usage report.

  1. Confirm the Optimization LLM provider in the header and the coding model used for savings estimates.
  2. Leave Deep Analysis unchecked for standard mode: up to 100 prioritized files and up to 500 suggestions. Enable it to review all eligible nonempty scanned files without the overall suggestion cap. Cloud prompts still use bounded context.
  3. Select Generate Optimization Suggestions. Progress and ETA apply to measured processing stages; cloud response time may remain unknown.
  4. Review token savings, estimated USD savings, Copilot credit savings where applicable, priority, confidence, maintainability, and CPU/memory/response-time impact.
  5. Select Show Change to compare before/after code. Some suggestions are structural guidance and do not have a single replacement snippet.
  6. Use Verify Change or Verify All Changes for advisory checks, then sort or page through results.

Cloud provider failures, including missing or rejected credentials, appear in a popup with guidance. Update the key in Settings or check Copilot sign-in, then generate again. Local heuristic recommendations are retained where possible and identified in the popup; a report marked local fallback or standard confidence is not a successful cloud research run. If the optimization request itself fails, no new report is generated.

Reading the result summary

Suggestions generated by identifies the advisor provider and whether the report used cloud research or an offline fallback. This report-level status is separate from the confidence rating of each recommendation. Pricing model identifies the coding model used to convert projected token savings into USD and, for Copilot, AI Credits.

Total projected savings adds the estimated token and USD savings from the returned suggestions, across all pages. The suggestion count is not a count of unique files: one file can have several recommendations. These totals describe the current report, not a daily or monthly saving, and do not mean changes have already been applied. GitHub AI Credits are shown only for Copilot pricing.

Average CPU, memory, and response-time savings are unweighted arithmetic means of the percentage changes estimated for each recommendation. Decreases count as positive savings; increases are labeled as increases. They are model-generated projections, not measured benchmarks. If values cannot be computed, the interface shows Unavailable.

Understanding each result column

Click the small ? beside any optimization column header for a short explanation. Click outside the popup or press Escape to close it.

Optimization results explained

Verification results and traffic lights

Verification uses local rule-based checks on the suggestion and file type. It does not compile or execute your project, run its tests, or prove that the replacement preserves behavior.

  • Critical (red): a known high-risk pattern was detected, such as comments proposed for JSON or removal of required syntax. Do not apply the proposed edit as written; inspect and correct it.
  • Medium (amber): contextual review is required. Identical lines can have different purposes, so removing one may delete meaningful behavior or data.
  • OK (green): the local checks did not flag a covered issue, or the suggestion is structural guidance without a generated edit. This is not a guarantee of safety.
  • The change was not verified: no verification result is available yet. Use Verify Change for one row or Verify All Changes for every suggestion, including other pages. A verification error is not an OK verdict.

Sorting, paging, and choosing what to apply

Click Filter beside Sort By to open a popup with three sidebar categories. In Performance Effect, CPU, Memory, Response Time, and Tokens each have one 0–100 percent track with separate minimum and maximum handles. Drag either handle, or focus it and use the keyboard arrow keys. A changed range matches decreases (or token savings) within its inclusive bounds. Unchanged 0–100 means no restriction. Checking Increases disables that metric's handles and matches any positive increase regardless of percentage; for tokens this means negative token savings. Unchecking restores the saved range.

In Impact, Priority, Confidence, and Maintainability each offer High, Medium, and Low checkboxes. Change Verification status offers OK, Medium, Critical, and Not Verified; Not Verified includes pending checks and failed requests without a completed verdict. Row errors remain visible. Within a checkbox group, any selected value matches; no selections means no restriction. Different groups and active metric ranges must all match.

Filters update results immediately across the full report before pagination. The popup shows matching versus total suggestions. Close it using Show results, Close, Escape, or the backdrop; selections are retained. Use Clear filters to restore every row. Filters affect only the table: projected totals, exports, and Verify All Changes still cover the full report, including hidden rows. The Performance Effect, Impact, and Action help popups explain each displayed item separately.

Verify All Changes processes every suggestion with at most four requests at a time, including rows on other pages. The progress summary shows how many checks finished, how many returned verdicts, and how many failed. A Critical or Medium verdict counts as a completed verification, not a failed request. Failed rows display their error; retry them with Verify Change, or rerun the full set. Generating new suggestions and exporting results are disabled while verification is running so the report is not replaced or exported partway through the checks.

Results display 50 suggestions per page. Use Previous and Next to navigate. Sort By orders the full report by Name, tokens saved (currently labeled Tocken Saved), or Verification Status; the arrow toggles ascending and descending order. Sorting by verification is not sorting by priority or savings. Excel and PDF exports include all suggestions, not only the current page.

Start with recommendations that combine useful savings, a clear rationale, and manageable risk. Inspect the before/after code, read any verification explanation, then apply one coherent change at a time and test it. If two rows target the same lines or refactor the same logic, choose compatible changes and reassess the savings rather than applying both blindly.

Example: interpreting a savings result

A suggestion showing 10,000 tokens saved with Claude Sonnet 4.6 pricing represents about $0.03 of avoided uncached input at the bundled $3-per-million rate. Under the Copilot Sonnet profile, that is also 3 AI Credits. It is not a $0.03 monthly saving unless your actual usage avoids those tokens once each month; repeated context loading can change realized savings.

Review before applying. Suggestions and verification results are advisory, not proof of correctness or measured runtime benchmarks. The preview does not edit your source. Apply chosen changes separately and run your own tests.

Projected savings price the estimated input tokens avoided using the coding-model selection. They do not measure cash refunded, include the optimizer's own cloud charge, or guarantee that overlapping suggestions can be added together without double counting.

7. Understand tokens, credits, and USD

Prices below describe the app's current built-in standard text-token rates. They are not fetched live and may change at the provider. Amounts are USD per one million tokens.

Supported pricing profiles
Provider / modelInputCache readCache writeOutput
Copilot or Claude Code / Opus 4.8$5.00$0.50$6.25$25.00
Copilot or Claude Code / Sonnet 4.6$3.00$0.30$3.75$15.00
Copilot / GPT-5.3 Codex$1.75$0.175Not applicable$14.00
 
USD = (input tokens x input rate
     + output tokens x output rate
     + cache-read tokens x cache-read rate
     + cache-write tokens x cache-write rate) / 1,000,000

GitHub Copilot AI Credits = USD / 0.01

Input, cache-read, and cache-write categories are priced separately. GitHub credits are rounded for reporting, so tiny savings can show zero credits even when USD is nonzero.

Sonnet example

For 100,000 input tokens and 20,000 output tokens, with no cache usage:

Input:   100,000 / 1,000,000 x $3  = $0.30
Output:   20,000 / 1,000,000 x $15 = $0.30
Total:                              $0.60
Copilot equivalent:                 60 AI Credits

For Claude Code, report $0.60, not GitHub credits. A static scan of only the 100,000 input tokens would report $0.30.

Important distinctions

  • Claude Code: USD is an API-rate equivalent, not a per-token invoice for a Claude subscription.
  • Copilot: AI Credits use the documented $0.01 conversion. Plan allowances, discounts, taxes, and actual additional charges are not modeled.
  • Ollama Cloud: selected candidates use bundled peak reference API rates retrieved 2026-11-22. For example, GPT-OSS 120B uses $0.15 input and $0.60 output per million tokens. Prices may change and off-peak rates are not assumed. Unknown or partially published rates show unavailable when needed; GitHub credits do not apply. This is not an Ollama account bill, and does not include subscription, local hardware or electricity costs.
  • Token estimates: GPT-5.3 Codex uses a local OpenAI-family tokenizer. Sonnet uses an approximate four-characters-per-token ratio; Opus 4.8 applies an approximate 1.3 multiplier. These are not provider-authoritative counts.
  • Dynamic totals: the selected model prices all recorded input, output, and cache tokens, regardless of the original session provider. This is a hypothetical scenario, not actual Ollama usage or billing; Ollama account logs are not fetched. Input and cache-read are treated as separate categories; nonzero cache-write tokens make Ollama costs unavailable because no corresponding rate is published. Selecting Copilot shows GitHub credit equivalents; Claude and Ollama do not. Older reports without a pricing selection retain recorded-model pricing until a model is selected.
  • Unavailable: means missing pricing or unsupported attribution, not free usage. Loading a saved analysis automatically refreshes prices from its stored counts; incomplete usage details or unknown models still remain unavailable.

Check current official rates at GitHub Copilot model pricing and Anthropic model pricing.

8. Dashboard

Run a static analysis to populate the dashboard. It presents repository totals, an executive summary, platform comparisons, language and largest-file charts, plus dynamic usage and optimization summaries when available.

Platform comparisons are illustrative estimates, not evidence that each platform was actually used. Microsoft 365 values are workload analogies, not a supported dynamic billing report.

Select Export Full Report to PDF to include the available analyses, optimization summary, and rendered charts in one report.

9. Save and load analyses

Save Analyses and Load Analyses appear in both analysis tabs.

  1. Run at least one analysis, then select Save Analyses.
  2. The app saves a snapshot under Session\<provider>_dd_mm_yyyy_hh_mm_ss\analysis.json in the application root for source runs, or under %LOCALAPPDATA%\AI Usage Analyzer in the packaged app. The status message shows the actual location.
  3. To restore it, select Load Analyses, choose a Saved session, and select Load Selected.

The snapshot preserves available static and dynamic reports, optimization results, paths, provider and pricing-model selections, generated-file exclusion, and Deep Analysis selection. Loading replaces the current snapshot; save current work first if you need to keep it.

Loading or saving automatically refreshes USD and Copilot credit estimates using stored token counts and the bundled pricing catalog. It does not rescan source files, reread session logs, or rerun cloud optimization. Loading leaves the original saved file unchanged; select Save Analyses to keep refreshed prices in a new snapshot. Unknown models or incomplete usage details remain unavailable.

Token counts and recommendations remain snapshots of the original analysis. Rerun the relevant analyses if your source files or session logs changed. Verification indicators are transient UI state rather than a separately restored verification history.

11. Settings and tooltips

About and User Guide

Select the gear icon to the right of Exit to open the Settings popup. Its About section identifies the software and version. Select Open User Guide to open USER_GUIDE.html in a new browser tab. The Contact link opens a new email addressed to sem.dev@gmail.com with the subject AI Usage Analizer.

Update API keys

Select Update Keys to open the key replacement dialog. Each credential displays Set or Not Set based on whether the running backend has a non-empty value; Unknown means status could not be loaded. Status does not check validity, expiration, or balance. Copilot CLI or GitHub CLI sign-in is separate from the token shown here. Enter a replacement in its masked field and select the adjacent Apply; other fields and existing values are unchanged. Existing values are never loaded into the form or returned by the backend. New values are saved to the configured local environment file and applied to the running server immediately. Source runs normally use backend\.env; packaged runs use %LOCALAPPDATA%\AI Usage Analyzer\.env. Treat keys as secrets and do not share screenshots of the dialog while typing.

Analysis preferences

Exclude lockfiles / generated files controls whether recognized lockfiles contribute to scan totals. Keep it enabled for a clearer view of hand-maintained code, or disable it when those files are relevant to your workload. Rerun static analysis after changing it.

Tooltips and ? popups

Hover over buttons, text inputs, selectors, links, and labeled controls to read their contextual tooltips. Select the small ? beside a heading or setting for a longer explanation of the data, estimates, and limitations. Help is available throughout Static Analysis, Dynamic Analysis, Dashboard, Optimization, session details, and Settings. Click outside a popup or press Escape to close it. Help text explains the interface; it does not change calculations.

Controls can be disabled while analysis, loading, saving, or exporting is active. Wait for the operation to finish before changing settings.

To print this guide or save it as PDF, use your browser's print command. This HTML file has no external assets, scripts, fonts, or network dependencies; only the documentation links open external pages.

12. Privacy and limitations

  • Static scanning and supported dynamic log parsing are local. Scanned repository code is not executed by those analyses.
  • Cloud optimization can send source excerpts, prompts, and usage context to the selected provider and consume its allowance. Only enable it for repositories and logs you are authorized to share with that provider.
  • Saved snapshots and exports can contain private code, absolute local paths, and chat/prompt data. Store and share them accordingly.
  • Do not assume scanning applies every repository-specific ignore rule or redacts secrets automatically.
  • Usage is limited by the files and log formats that can be parsed. The app is not a complete provider billing ledger.
  • Optimization estimates and CPU/memory/latency effects are projections. Validate changes against your own workloads.

13. Troubleshooting

Claude Sonnet USD shows Unavailable

Load the saved analysis to automatically refresh pricing without a full rerun. Restart the backend first if you just updated the app. Select a supported coding model to price dynamic totals from recorded counts even when historical model names are unknown. Individual breakdowns with missing cache attribution can remain unavailable. Claude credits are intentionally unavailable.

No dynamic sessions were found

Use an existing folder containing supported Claude JSONL or legacy Copilot events files, not current Copilot binary databases. Use your actual expanded Windows user path and a directory close to the logs. Try omitting the optional repository filter; sessions without recognized edit/write tools in that directory will be filtered out.

The Optimization tab asks for both analyses

Run or load both reports first. A model change or clearing static results can invalidate the optimization prerequisite. If only a static report was saved, you still need a dynamic analysis.

Cloud optimization is unavailable

Read the reported provider error. Check account access, network connectivity, backend credentials, and any configured Copilot model ID. Restart after environment changes. Local fallback recommendations can still be available, but they are not cloud-generated results.

Tokens or costs differ from the provider bill

Static analysis estimates an input pass, not an entire development session. Local tokenization, incomplete logs, context reuse, cache behavior, output tokens, subscription allowances, and provider pricing changes can all cause differences. Check the report's model and pricing notes.

The browser cannot reach the app

Check both development-server windows for startup errors. The browser normally uses port 5173 and the frontend proxies API requests to backend port 4000. If the ports differ, check the project configuration. A missing corporate certificate warning should be resolved using your organization's approved CA configuration, never by disabling TLS verification.

A saved report cannot be loaded

The app rejects incomplete or incompatible snapshots. Select a valid folder created by Save Analyses; do not substitute a PDF, workbook, or standalone dynamic JSON export. Preserve the original file and rerun analyses if necessary.
